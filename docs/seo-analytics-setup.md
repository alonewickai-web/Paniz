# اتصال سئو و گزارش بازدید پانیذ

صفحهٔ «سئو و تحلیل بازدید» از API احراز هویت‌شدهٔ فروشگاه استفاده می‌کند. بازه‌های ۷، ۲۸، ۹۰ روزه و دلخواه، نمودار مقایسهٔ دوره‌ها، کلمات جست‌وجو، عملکرد محصولات، منابع ورود، دستگاه‌ها و خروجی CSV و Excel آماده‌اند. دادهٔ فروش از سفارش‌های پرداخت‌شدهٔ دیتابیس خوانده می‌شود.

## تنظیم حساب‌های گوگل

1. دامنهٔ `panizstyle.ir` را در Google Search Console ثبت و مالکیت آن را با رکورد TXT رسمی گوگل در DNS تأیید کن. مقدار property باید دقیقاً مطابق پنل باشد؛ برای Domain property نمونهٔ آن `sc-domain:panizstyle.ir` است و برای URL-prefix نمونهٔ آن `https://panizstyle.ir/` است.
2. در GA4 یک property و Web data stream برای سایت بساز. شناسهٔ property یک عدد است و Measurement ID با `G-` شروع می‌شود.
3. در Google Cloud پروژه‌ای بساز و Search Console API و Google Analytics Data API را فعال کن. یک Service Account اختصاصی گزارش‌ها ایجاد کن.
4. ایمیل Service Account را به property در Search Console با دسترسی مشاهدهٔ گزارش‌های عملکرد و به GA4 با نقش Viewer اضافه کن. بک‌اند از scopeهای فقط خواندنی استفاده می‌کند.
5. فایل کلید Service Account را در محل امن مالک نگه دار. مقدار `client_email` و `private_key` فقط در تنظیمات سرور قرار می‌گیرند؛ فایل JSON را در Git یا APK قرار نده.

## تنظیم سرور

فایل موجود `.env.server` را ویرایش کن و این متغیرها را اضافه کن. فایل فعلی حاوی اطلاعات دیتابیس و سرویس‌هاست؛ آن را دوباره تولید نکن.

```dotenv
GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account-email
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="private-key-with-escaped-newlines"
GOOGLE_SEARCH_CONSOLE_SITE_URL=https://panizstyle.ir/
GA4_PROPERTY_ID=property-number
NEXT_PUBLIC_GA4_MEASUREMENT_ID=G-MEASUREMENTID
GA4_CURRENCY_CODE=IRR
SEO_ALERT_DROP_PERCENT=30
SEO_ALERT_POSITION_DROP=3
GOOGLE_ANALYTICS_SYNC_ENABLED=true
```

در private key، خط‌های جدید را با `\n` نگه دار. با `GA4_CURRENCY_CODE=IRR`، مبلغ گزارش مستقیماً از API گوگل به ریال درخواست و سپس به تومان تبدیل می‌شود. اگر ارز گزارش مشخص نشده باشد، مبلغ تومانی نمایش داده نمی‌شود. Measurement ID عمومی است و هنگام ساخت نسخهٔ سایت داخل مرورگر قرار می‌گیرد؛ کلید خصوصی فقط در API استفاده می‌شود.

مهاجرت `20261014130000_product_seo_canonical_redirects` فقط یک ستون اختیاری و جدول نگهداری آدرس‌های قبلی محصول اضافه می‌کند. اجرای مهاجرت باید پیش از اجرای API جدید باشد. این کار محصول، سفارش یا کاربر را حذف نمی‌کند. پس از تنظیم متغیرها، API و سایت را با روال استقرار فعلی دوباره بساز و اپ مدیریت جدید را نصب کن.

## وضعیت و تعریف آمار

- بدون دسترسی گوگل، وضعیت «نیازمند اتصال» و مقدار نامعلوم نمایش داده می‌شود.
- پس از دریافت موفق گزارش، وضعیت «متصل» و زمان واقعی دریافت نمایش داده می‌شود. شکست درخواست به‌صورت خطای همان منبع نشان داده می‌شود.
- گزارش‌ها پنج دقیقه کش می‌شوند و با تنظیم اتصال، گزارش ۲۸ روزه هر ۳۰ دقیقه در پس‌زمینه تازه می‌شود.
- Search Console همهٔ عبارت‌های جست‌وجو را ارائه نمی‌کند؛ جدول فعلی حداکثر هزار ردیف گزارش‌شده را دارد. نبود ردیف یک محصول، اثبات صفر بودن ترافیک آن نیست.
- نرخ تبدیل فروشگاه برابر تعداد سفارش‌های پرداخت‌شدهٔ ثبت‌شده در بازه تقسیم بر تعداد نشست‌های GA4 در همان بازه است. نرخ تبدیل محصول برابر سفارش پرداخت‌شدهٔ شامل آن محصول تقسیم بر بازدید صفحهٔ همان محصول است. این دو معیار جدا تعریف شده‌اند.
- روزهای دیتابیس با وقت تهران محاسبه می‌شوند. Search Console و GA4 از منطقهٔ زمانی گزارش خود استفاده می‌کنند.
- درآمد جست‌وجوی گوگل از `purchaseRevenue` با منبع `google` و رسانهٔ `organic` خوانده می‌شود. نمایش مبلغ به دسترسی مالی مدیر نیاز دارد.
- اطلاعات تلفن، ایمیل، نشانی و یادداشت مشتری به GA4 ارسال نمی‌شوند. رویدادهای مشاهدهٔ محصول، افزودن به سبد و شروع تسویه‌حساب فقط اطلاعات کالا را می‌فرستند.
- رویداد `purchase` فقط برای پاسخ سفارش با `paymentStatus=paid` اجرا می‌شود. درگاه و مسیر تأیید پرداخت فعلی فروشگاه هنوز خرید موفق را ایجاد نمی‌کنند؛ سفارش پرداخت‌نشده عمداً به‌عنوان خرید موفق ثبت نمی‌شود. پس از تکمیل درگاه، همین شرط باید در مسیر بازگشت/تأیید پرداخت اجرا شود.
- وضعیت ایندکس و Core Web Vitals تا اتصال منبع رسمی مربوطه «نامشخص» است. بررسی خارجی sitemap نیز در این نسخه انجام نشده است.

## سئوی محصول و گزارش فایل

در افزودن و ویرایش محصول، عنوان، توضیح، slug، canonical و پیش‌نمایش تقریبی گوگل وجود دارد. پیشنهاد متن از مشخصات واقعی محصول ساخته می‌شود. متن جایگزین هر تصویر از ویرایشگر تصویر قابل تغییر است. تغییر slug، آدرس قبلی را نگه می‌دارد و درخواست سایت به مسیر جدید با ۳۰۱ هدایت می‌شود. محصولات ناموجود منتشرشده در سایت و sitemap باقی می‌مانند.

سایت برای محصولات و دسته‌بندی‌ها metadata، canonical، Open Graph، Twitter Card و اطلاعات ساخت‌یافتهٔ محصول و مسیر صفحه تولید می‌کند. قیمت اطلاعات ساخت‌یافته و GA4 به ریال است و از قیمت تومانی واقعی کالا تبدیل می‌شود. sitemap در هر درخواست از کاتالوگ تازه خوانده می‌شود. صفحات خصوصی دارای `noindex` هستند.

APIهای گزارش فقط با نشست معتبر مدیر و دسترسی `reports.view` در دسترس‌اند:

```text
GET /api/v1/admin/analytics/seo?range=28
GET /api/v1/admin/analytics/seo?range=custom&from=2026-10-01&to=2026-10-14
GET /api/v1/admin/analytics/seo/export.csv?range=28&type=products
GET /api/v1/admin/analytics/seo/export.xlsx?range=28&type=summary
```

نوع گزارش می‌تواند `products`، `queries`، `pages` یا `summary` باشد. خروجی محصول فیلتر `category` هم دارد. در اندروید، دکمهٔ ذخیره از انتخاب‌گر فایل خود سیستم استفاده می‌کند و اجازهٔ دسترسی عمومی به حافظه نمی‌خواهد.
