# حساب مشتری و خرید با ورود اجباری

## رفتار مشتری

- مشتری با شمارهٔ موبایل و کد یک‌بارمصرف وارد می‌شود؛ اگر قبلاً حساب نداشته باشد، همان‌جا حسابش ساخته می‌شود.
- نشست ۳۰ روزه در کوکی `HttpOnly` قرار می‌گیرد و فقط hash توکن نشست در دیتابیس می‌ماند.
- اطلاعات نام و ایمیل، شمارهٔ تأییدشده، چند نشانی تحویل و سفارش‌های مشتری در صفحهٔ `/account` قابل مدیریت است.
- نشانی شامل استان، شهر، خیابان، کوچه، پلاک، واحد، توضیحات پیک، نام و تلفن گیرنده و کدپستی ۱۰ رقمی است.
- ارسال سفارش فقط برای نشست معتبر و نشانی متعلق به همان حساب انجام می‌شود. سفارش نسخهٔ ثابت اطلاعات نشانی را ذخیره می‌کند تا ویرایش نشانی در آینده روی سفارش قبلی اثر نگذارد.
- سبد خرید تا هنگام ورود در همان مرورگر حفظ می‌شود.

## مسیرهای API

| روش و مسیر | کاربرد |
|---|---|
| `POST /customer/auth/send-code` | درخواست کد ورود، با محدودیت ارسال مجدد و سقف روزانه |
| `POST /customer/auth/verify-code` | تأیید کد، ساخت مشتری در اولین ورود و صدور کوکی نشست |
| `GET /customer/auth/me` | هویت نشست جاری |
| `POST /customer/auth/logout` | ابطال نشست و پاک‌کردن کوکی |
| `GET/PATCH /customer/profile` | نمایش یا ذخیرهٔ نام و ایمیل |
| `GET /customer/orders` | تاریخچهٔ سفارش‌های همان مشتری |
| `GET/POST /customer/addresses` | فهرست یا افزودن نشانی |
| `PATCH/DELETE /customer/addresses/:id` | ویرایش یا حذف نشانی متعلق به مشتری |
| `POST /customer/addresses/:id/default` | تعیین نشانی پیش‌فرض |
| `POST /orders` | سفارش احراز‌شده با `addressId` و اقلام سبد |

## پیامک و راه‌اندازی

محیط توسعه به‌صورت پیش‌فرض از ارسال آزمایشی استفاده می‌کند و کد را در پاسخ API برای تکمیل جریان محلی برمی‌گرداند. این حالت در `NODE_ENV=production` غیرفعال است. پیش از انتشار باید:

1. سرویس پیامک مورد استفادهٔ فروشگاه انتخاب و adapter آن تنظیم شود.
2. یک `CUSTOMER_AUTH_SECRET` تصادفی و حداقل ۳۲ کاراکتری در محیط API قرار گیرد.
3. `WEB_ORIGINS` شامل دامنهٔ واقعی سایت باشد تا کوکی نشست همراه درخواست‌های مجاز ارسال شود.
4. `Start.bat` یا `npm run prisma:migrate:deploy` migration مشتری را روی دیتابیس اجرا کند.

کدها ۵ دقیقه اعتبار دارند، پس از ۵ تلاش ناموفق قفل می‌شوند، ارسال مجدد ۶۰ ثانیه فاصله دارد و برای هر شماره سقف ۵ درخواست در ۲۴ ساعت اعمال می‌شود. درگاه پرداخت و روش ارسال مستقل از ورود مشتری هستند و تا اتصالشان پرداخت بانکی نهایی انجام نمی‌شود.

## bypass موقت کد ورود در توسعه

برای ورود محلی، مقدار `CUSTOMER_OTP_BYPASS=true` در `apps/api/.env` هر کد شش‌رقمی را برای درخواست OTP معتبر می‌کند. این گزینه فقط وقتی `NODE_ENV=development` فعال است؛ در production نادیده گرفته می‌شود. پس از تغییر، API را دوباره اجرا کنید.
