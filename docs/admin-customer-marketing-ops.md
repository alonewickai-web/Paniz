# راه‌اندازی ابزارهای مدیریتی PANIZ

این نسخه API و صفحه‌های اپ مدیر را برای مشتریان، کد تخفیف، کمپین پیامک و روبیکا، انتشار شبکه‌های اجتماعی و پشتیبان دیتابیس آماده می‌کند. migration دیتابیس باید در محیط Railway جداگانه اجرا شود.

## مشتریان و رضایت پیامک

- فهرست مشتریان از اپ مدیر بر اساس نام/شماره، شهر، زمان عضویت، آخرین خرید یا محصولی که خریده‌اند فیلتر می‌شود.
- دریافت پیامک تبلیغاتی فقط برای مشتریانی انجام می‌شود که در صفحهٔ حساب کاربری فروشگاه گزینهٔ دریافت پیامک را خودشان فعال کرده‌اند. پیش‌فرض مشتریان قبلی خاموش است و مدیر نمی‌تواند رضایت را به‌جای مشتری فعال کند.
- رضایت پیامک از رضایت روبیکا جداست؛ مدیر نمی‌تواند هیچ‌کدام را برای مشتری فعال کند.
- فهرست کمپین در هر اجرا دوباره از روی فیلتر و رضایت فعلی ساخته می‌شود؛ تا ۲۰٬۰۰۰ مخاطب برای هر کمپین پشتیبانی می‌شود.

## کدهای تخفیف

در اپ مدیر، کد درصدی یا مبلغ ثابت، حداقل مبلغ سبد، سقف مبلغ تخفیف و وضعیت فعال را ثبت کنید. کد فعال در سبد خرید فروشگاه اعتبارسنجی و هنگام ثبت سفارش دوباره بررسی می‌شود. استفاده، سقف سراسری، سقف هر مشتری و فقط سفارش اول هم در مدل دیتابیس پشتیبانی شده‌اند؛ صفحهٔ فعلی اپ فقط تنظیمات پایه را ویرایش می‌کند.

## پیامک SMS.ir

این متغیرها را فقط در Variables سرویس API در Railway ثبت کنید؛ کلید را در Git، APK یا گفتگو قرار ندهید:

| متغیر | توضیح |
| --- | --- |
| `SMSIR_API_KEY` | کلید API پنل SMS.ir |
| `SMSIR_LINE_NUMBER` | خط خدماتی/ارسالی مجاز |
| `SMSIR_BULK_URL` | نشانی پیش‌فرض API ارسال گروهی |

اپ قبل از ساخت کمپین تعداد مخاطبان رضایت‌داده را پیش‌نمایش می‌دهد و پیش از ارسال تأیید مدیر می‌گیرد. درخواست ارسال وارد صف API می‌شود و در دسته‌های ۱۰۰تایی پردازش می‌شود. شمارندهٔ پذیرفته‌شده توسط API پیامک است و رسید تحویل به گوشی نیست. اگر کمپین نیمه‌کاره شد، پیش از ساخت کمپین جایگزین گزارش پنل SMS.ir را بررسی کنید تا ارسال تکراری نشود.

## روبیکا و اینستاگرام

متغیرهای محرمانهٔ لازم در سرویس API:

| متغیر | توضیح |
| --- | --- |
| `RUBIKA_BOT_TOKEN` | توکن باتی که از BotFather روبیکا ساخته شده |
| `RUBIKA_CHANNEL_ID` | شناسهٔ کانال مقصد؛ بات باید در آن مجوز ارسال داشته باشد |
| `INSTAGRAM_USER_ID` | شناسهٔ حساب حرفه‌ای متصل به Meta |
| `INSTAGRAM_ACCESS_TOKEN` | توکن دارای مجوز انتشار |
| `INSTAGRAM_GRAPH_API_VERSION` | نسخهٔ Graph API فعال و مجاز برای برنامهٔ Meta |

پست‌ها در صف زمان‌بندی ذخیره و توسط worker API پردازش می‌شوند. اینستاگرام برای هر پست تصویر عمومی HTTPS لازم دارد؛ API ابتدا container رسانه را می‌سازد و سپس آن را منتشر می‌کند. روبیکا متن کپشن و در صورت وجود، پیوند تصویر را در کانال می‌فرستد. حساب Meta باید حرفه‌ای باشد و برنامهٔ Meta مجوز محتوای انتشار را داشته باشد. وضعیت هر کانال در سابقهٔ پست ثبت می‌شود.

## پیام خصوصی مشتریان با بات روبیکا

این قابلیت برای پیام خصوصی به مشتریانِ متصل‌شده است و با انتشار در کانال روبیکا تفاوت دارد:

1. توکن BotFather را فقط در Variables سرویس API با نام **RUBIKA_BOT_TOKEN** ذخیره کنید؛ توکن را در Git، APK یا گفتگو قرار ندهید.
2. مقدار **RUBIKA_WEBHOOK_BASE_URL** را روی نشانی HTTPS عمومی API بگذارید، برای نمونه https://api-production-bbf4.up.railway.app. پس از راه‌اندازی API، webhook رویدادهای ReceiveUpdate برای بات ثبت می‌شود.
3. مشتری وارد سایت شود، رضایت روبیکا را فعال و دکمهٔ اتصال را بزند. کد یک‌بارمصرف ده دقیقه اعتبار دارد؛ مشتری باید بات را باز کند و کد را در گفت‌وگوی خصوصی آن بفرستد.
4. مدیر در اپ اندروید، صفحهٔ «پیام‌رسانی به مشتریان» و روش «پیام خصوصی ربات روبیکا» را انتخاب می‌کند. مخاطبان فقط از میان حساب‌های متصل و دارای رضایت فعال انتخاب می‌شوند. فیلترهای شهر، زمان ثبت‌نام، محصول و آخرین خرید هم اعمال می‌شوند.
5. مشتری برای قطع پیام تبلیغاتی می‌تواند در چت بات /stop بفرستد یا در سایت رضایت را خاموش/اتصال را قطع کند.

متغیر RUBIKA_CHANNEL_ID فقط برای انتشار پست در کانال لازم است و برای پیام خصوصی کمپین استفاده نمی‌شود. RUBIKA_BOT_API_BASE_URL و RUBIKA_SEND_DELAY_MS اختیاری‌اند؛ مقدار پیش‌فرض API رسمی و فاصلهٔ ۱۵۰ میلی‌ثانیه است.

### رفع migration شکست‌خوردهٔ قبلی

در محیط تولید، migration 20261011160000_admin_commerce_tools با خطای BOM قبل از اجرای نخستین دستور SQL متوقف شده است؛ بنابراین در تاریخچهٔ Prisma با وضعیت failed مانده و migrationهای بعدی تا زمان resolve اجرا نمی‌شوند. BOM فایل اصلاح شده است. پس از اطمینان از اینکه خطای ثبت‌شده همچنان خطای نخستین دستور است و هیچ‌کدام از جدول‌های این migration ایجاد نشده‌اند، در محیط API متصل به دیتابیس production این دو دستور را به‌ترتیب اجرا کنید:

    npx prisma migrate resolve --rolled-back 20261011160000_admin_commerce_tools
    npx prisma migrate deploy

این دستورات را با DATABASE_URL تولید اجرا کنید، نه روی دیتابیس محلی. در Railway CLI، ابتدا پروژه و environment تولید را link کنید و سپس فرمان‌ها را در context همان سرویس اجرا کنید. اگر migration بخشی از جداول را ساخته باشد، پیش از resolve باید وضعیت واقعی دیتابیس بررسی شود.

## وضعیت و پشتیبان‌گیری

برای ماندگاری backup پس از restart/deploy، در سرویس API در Railway یک Volume به مسیر `/data` وصل کنید و این مقادیر را ثبت کنید:

```text
BACKUP_DIR=/data/backups
BACKUP_RETENTION_COUNT=7
BACKUP_SCHEDULE_ENABLED=true
```

ایمیج API اکنون `mysqldump` را نصب می‌کند. API هر ساعت بررسی می‌کند که backup روزانه وجود داشته باشد، نسخه‌های دستی را هم پشتیبانی می‌کند و فایل‌های قدیمی‌تر از سقف نگهداری را پاک می‌کند. صفحهٔ عملیات، دسترسی نوشتن Volume و فایل‌های موجود را نشان می‌دهد. تا وقتی `BACKUP_DIR` به Volume پایدار وصل نشده باشد، فایل پشتیبان ممکن است با جایگزینی کانتینر از بین برود.

## مسیرهای مدیریتی

تمام مسیرهای زیر زیر `/api/v1` هستند و نشست مدیر می‌خواهند:

- `GET /admin/customers`, `GET /admin/products/options`
- `GET/POST/PATCH /admin/coupons`
- `POST /admin/sms-campaigns/preview`, `GET/POST /admin/sms-campaigns`, `POST /admin/sms-campaigns/:id/send`
- `GET /admin/social/status`, `GET/POST /admin/social/posts`
- `GET /admin/operations/status`, `GET/POST /admin/operations/backups`
- POST /admin/rubika-campaigns/preview، GET/POST /admin/rubika-campaigns و POST /admin/rubika-campaigns/:id/send
- POST /customer/rubika/link-code و DELETE /customer/rubika/link
- POST /integrations/rubika/webhook/:secret (وب‌هوک عمومی با مسیر مشتق‌شده از توکن بات)

بدون متغیرهای اتصال، صفحه‌ها وضعیت «تنظیم نشده» را نشان می‌دهند و اتصال زنده انجام نمی‌شود.
