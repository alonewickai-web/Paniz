# PanizStyle

فروشگاه اینترنتی فارسی و راست‌چین پوشاک زنانه، همراه با API و اپ اندرویدی مدیریت فروشگاه. وب‌سایت و اپ مدیر از API مرکزی استفاده می‌کنند؛ اپ مدیر مستقیماً به MySQL وصل نمی‌شود.

> **وضعیت استقرار:** مقصد استقرار، سرور ایران با Ubuntu و Docker است؛ راه‌اندازی مرحله‌به‌مرحله در [راهنمای استقرار سرور ایران](docs/deploy-arvan.md) آمده است. دیتابیس جدید و خالی ساخته می‌شود و داده‌های سرویس قبلی به آن منتقل نمی‌شوند. سورس اپ مدیر روی نسخهٔ `1.0.10+2026101201` و API ایران تنظیم شده؛ APK تازه باید بعد از فعال‌شدن دامنه ساخته شود. حساب اولیهٔ مدیر `erfan` / `2018` است؛ گذرواژه را بلافاصله بعد از اولین ورود عوض کنید.

## اجزای مخزن

| مسیر | محتوا |
| --- | --- |
| **app/** | وب‌سایت فروشگاه با Next.js |
| **apps/api/** | API با NestJS، Prisma و MySQL |
| **apps/admin-mobile/** | اپ Flutter اندرویدی مدیر |
| **database/** | تنظیمات Docker Compose دیتابیس MySQL |
| **APK/** | APKهای Release جداشده بر اساس معماری پردازنده |
| **docs/admin-api.md** | راه‌اندازی مدیر و قرارداد API مدیریت |
| **docs/customer-account.md** | ورود مشتری، نشانی‌ها و فرایند سفارش |
| **docs/data-model.md** | مدل داده و قواعد موجودی و سفارش |

نشانی‌های نهایی پس از تغییر DNS: `https://panizstyle.ir` برای فروشگاه و `https://api.panizstyle.ir/api/v1` برای API. اتصال DNS در Cloudflare و صدور HTTPS در راهنمای استقرار سرور ایران توضیح داده شده است.

## پیش‌نیازها

برای اجرای محلی در Windows لازم است:

- Windows 10 یا 11
- Docker Desktop باز و آمادهٔ اجرا، با Docker Compose
- Node.js نسخهٔ 20.19 یا جدیدتر و npm در PATH
- Chrome برای بازشدن خودکار سایت؛ اگر Chrome پیدا نشود، مرورگر پیش‌فرض باز می‌شود

برای ساخت اپ Android علاوه بر این‌ها Flutter، Android SDK و Java لازم است. راهنمای کامل در **apps/admin-mobile/README.md** است.

## اجرای سریع در Windows

بار اول، در PowerShell و از ریشهٔ مخزن، فایل‌های محیط محلی را بسازید:

~~~powershell
Copy-Item database/.env.example database/.env -Force
Copy-Item apps/api/.env.example apps/api/.env -Force
~~~

مقادیر نمونهٔ این فایل‌ها فقط برای رایانهٔ توسعه هستند. اگر گذرواژهٔ MySQL را در **database/.env** عوض کردید، مقدار متناظر در **apps/api/.env** و نشانی **DATABASE_URL** را هم هماهنگ کنید. فایل‌های **.env** را در Git قرار ندهید.

سپس Docker Desktop را باز کنید و **Start.bat** را از ریشهٔ پروژه اجرا کنید. راه‌انداز:

1. MySQL را بالا می‌آورد و تا آماده‌شدن دیتابیس صبر می‌کند.
2. در صورت نیاز وابستگی‌های API و وب را نصب و Prisma Client را تولید می‌کند.
3. migrationهای Prisma و کاتالوگ نمونه را اعمال می‌کند.
4. API و وب‌سایت را در پس‌زمینه اجرا می‌کند.
5. Chrome را روی صفحهٔ فروشگاه باز می‌کند و خود فایل BAT می‌بندد.

گزارش‌ها در پوشهٔ **logs/** ذخیره می‌شوند. اگر اجرا ناموفق بود، ابتدا **logs/** و وضعیت Docker Desktop را بررسی کنید. بستن فایل BAT سرویس‌ها را متوقف نمی‌کند؛ API و وب‌سایت در پس‌زمینه می‌مانند. برای توقف MySQL:

~~~powershell
docker compose --project-directory database -f database/compose.yaml down
~~~

داده‌ها در volume محلی Docker با نام **panizstyle_mysql** هستند و با فرمان بالا پاک نمی‌شوند. سرویس‌های Node را از Task Manager متوقف کنید.

## قابلیت‌های فروشگاه

- صفحهٔ اصلی، دسته‌بندی‌ها، جست‌وجو، فیلتر و مرتب‌سازی محصولات
- صفحهٔ محصول با تصاویر، رنگ، سایز، قیمت و موجودی
- سبد خرید و محاسبهٔ دوبارهٔ قیمت از API
- حساب مشتری با ورود شمارهٔ همراه و کد یک‌بارمصرف
- ذخیرهٔ پروفایل و نشانی‌های تحویل؛ نشانی شامل استان، شهر، خیابان، کوچه، پلاک، واحد، توضیحات تحویل و کدپستی است
- نهایی‌کردن سفارش فقط برای مشتری واردشده و دارای نشانی ذخیره‌شده
- رزرو موقت موجودی هنگام ثبت سفارش و ثبت snapshot نشانی و اقلام سفارش
- پیگیری سفارش و نمایش تاریخچهٔ وضعیت آن
- علاقه‌مندی‌ها در حافظهٔ محلی مرورگر ذخیره می‌شوند

صفحه‌ها شامل **/**، **/products**، **/products/[slug]**، **/cart**، **/account**، **/checkout**، **/favorites**، **/about**، **/contact**، **/help/faq**، **/help/shipping** و **/policies/** هستند.

## API و دیتابیس

API با NestJS و Prisma اجرا می‌شود و MySQL 8.4 در Docker نگهداری می‌شود. نشانی پایهٔ مسیرها **/api/v1** است. API شامل این بخش‌هاست:

- کاتالوگ عمومی: دسته‌ها، محصولات، فیلترها و تنظیمات ویترین
- حساب مشتری: OTP، پروفایل، نشانی‌ها و تاریخچهٔ سفارش
- سفارش: محاسبهٔ قیمت سرور، ثبت سفارش، رزرو موجودی و پیگیری
- مدیریت: ورود مدیر، داشبورد، محصولات و تنوع‌ها، موجودی، سفارش‌ها، دسته‌ها، بنرها و ظاهر صفحهٔ اصلی
- سلامت سرویس: بررسی زنده‌بودن API و اتصال دیتابیس

فهرست دقیق مسیرهای مدیریتی، احراز هویت، محدودیت‌ها و نمونهٔ راه‌اندازی مدیر در [راهنمای API مدیریت](docs/admin-api.md) قرار دارد. برای جزئیات حساب مشتری و سفارش، [راهنمای مشتری](docs/customer-account.md) را ببینید.

## اجرای دستی برای توسعه

Docker Desktop را باز کنید و از ریشهٔ پروژه دیتابیس را اجرا کنید:

~~~powershell
docker compose --project-directory database -f database/compose.yaml up -d
~~~

در یک پنجرهٔ PowerShell جداگانه، API را اجرا کنید:

~~~powershell
Set-Location apps/api
npm.cmd install
npm.cmd run prisma:generate
npm.cmd run prisma:migrate:deploy
npm.cmd run prisma:seed
npm.cmd run start:dev
~~~

در پنجرهٔ دیگری، از ریشهٔ پروژه وب‌سایت را اجرا کنید:

~~~powershell
npm.cmd install
npm.cmd run dev
~~~

## اپ Android مدیریت

بخش‌های اپ مدیر شامل داشبورد، سفارش‌ها، محصولات و تنوع‌ها، اصلاح موجودی، دسته‌ها، بنرها، رنگ و چیدمان فروشگاه، مشتریان، کدهای تخفیف، کمپین‌های پیامکی، انتشار روبیکا/Instagram، وضعیت سرویس و پشتیبان‌گیری است. انتشار هر محصول از فهرست محصولات، تصویر اصلی و کپشن خودکار مشخصات کالا را به کانال روبیکا می‌فرستد. اتصال سرویس‌های بیرونی با متغیرهای محرمانه در `.env.server` سرور تنظیم می‌شود.

APKها را می‌توان از GitHub مستقیم گرفت:

| معماری | مناسب برای | دانلود |
| --- | --- | --- |
| ARM64 | بیشتر گوشی‌های اندرویدی جدید | [دانلود مستقیم](https://media.githubusercontent.com/media/alonewickai-web/Paniz/main/APK/PanizStyle-Admin-ARM64.apk) |
| ARMV7 | دستگاه‌های قدیمی ۳۲ بیتی | [دانلود مستقیم](https://media.githubusercontent.com/media/alonewickai-web/Paniz/main/APK/PanizStyle-Admin-ARMV7.apk) |

هر دستگاه فقط باید APK معماری سازگار خودش را نصب کند؛ برای بیشتر گوشی‌ها ARM64 را انتخاب کنید. این APKها برای نسخهٔ عملیاتی به URL واقعی HTTPS برای API نیاز دارند؛ جزئیات در **apps/admin-mobile/README.md** آمده است.

## تنظیم امنیت مدیر

در محیط آزمایشی با نام کاربری `erfan` و گذرواژهٔ `2018` وارد اپ مدیریت شوید؛ حساب فقط یک‌بار و خودکار توسط API ساخته می‌شود. این گذرواژه موقت است و باید پیش از استفاده روی سرور اصلی عوض شود. مراحل کامل در [راهنمای API مدیریت](docs/admin-api.md) آمده است.

برای production، **CUSTOMER_AUTH_SECRET** تصادفی و قوی، دامنه‌های واقعی در **WEB_ORIGINS** و HTTPS لازم‌اند. کلیدها و گذرواژه‌ها را در مخزن یا APK قرار ندهید.

## موارد لازم پیش از فروش واقعی

- کاتالوگ نمونه را با محصولات، تصاویر، رنگ‌ها، سایزها و موجودی واقعی جایگزین کنید.
- سرویس پیامک و adapter ارسال OTP را انتخاب و به API متصل کنید. در توسعه، کد آزمایشی در پاسخ API برمی‌گردد؛ گزینهٔ **CUSTOMER_OTP_BYPASS=true** فقط برای توسعه است و هر کد شش‌رقمی را می‌پذیرد.
- درگاه پرداخت و تأیید سمت سرور آن را پیاده‌سازی و تنظیم کنید. در وضعیت فعلی ثبت سفارش به معنی پرداخت بانکی نیست.
- روش ارسال، هزینه‌ها، مناطق تحت پوشش و کد رهگیری را تعیین کنید.
- دامنه، HTTPS، مقادیر production و پشتیبان‌گیری دیتابیس را تنظیم کنید.
- APK مدیریت با کلید ثابت Release امضا می‌شود؛ امضای ثابت به نصب به‌روزرسانی‌ها کمک می‌کند. برای توزیع عمومی، از Google Play Console و مسیر تست داخلی استفاده کنید؛ Play Protect ممکن است برای APKهای نصب‌شده از خارج Play هشدار منبع ناشناس نشان دهد.
- شمارهٔ پشتیبانی، ایمیل، زمان پاسخ‌گویی و سیاست‌های بازگشت کالا را با اطلاعات واقعی فروشگاه تکمیل کنید.

برای استقرار سایت، API و MySQL روی سرور ایران، [راهنمای استقرار سرور ایران](docs/deploy-arvan.md) را ببینید.

## عیب‌یابی

- **Docker یا دیتابیس بالا نمی‌آید:** Docker Desktop را باز کنید و گزارش **logs/database-start.log** را ببینید.
- **پیغام API قدیمی روی پورت 4000:** فرایند Node.js که در متن خطا مشخص شده را از Task Manager ببندید و دوباره **Start.bat** را اجرا کنید.
- **سایت یا API اجرا نمی‌شود:** گزارش‌های **logs/dev-server.err.log**، **logs/api-server.err.log**، **logs/api-build.log** و **logs/migration.log** را بررسی کنید.
- **خطای اتصال دیتابیس:** هماهنگی گذرواژه در **database/.env** و **apps/api/.env**، مقدار **DATABASE_URL** و اشغال نبودن پورت 3306 را بررسی کنید.
- **اپ روی گوشی به API وصل نمی‌شود:** در Debug از IP شبکهٔ رایانه به‌جای **10.0.2.2** استفاده کنید، API را روی شبکه در دسترس بگذارید و پورت 4000 را در فایروال Windows مجاز کنید. برای Release دامنهٔ HTTPS لازم است.
